ACON on open models: where its optimized compression breaks, and why

[Your name] · 3 November 2026 · base paper: Kang et al., ACON: Optimizing Context Compression for Long-horizon LLM Agents, ICML 2026

Summary

  1. ACON works on open models at the paper's own settings. With the paper's optimized guideline and the paper's history threshold (4,096 tokens), a qwen2.5-14B agent keeps or beats the uncompressed accuracy with 33% fewer agent tokens (dev: 73.2% vs 69.6%).
  2. The same guideline collapses under aggressive compression. At a 512-token threshold it falls to 42.9% on dev (p = 0.0005 vs 4,096) and to 45.2% vs 70.2% on the held-out test set (168 tasks, 54 tasks lost and 12 gained, p = 1.7 × 10⁻⁷). The paper's unoptimized starting guideline does not collapse (69.6% at both thresholds).
  3. Mechanism: the optimized guideline deletes failures. When the compressed history contains failed steps, its summaries mention them 32% of the time, against 87% for the unoptimized guideline. Compressing ~9 times per task, the agent forgets what already failed, keeps calling APIs that do not exist (46% of steps vs 36%) and runs into the step limit.
  4. ACON's combined-compression collapse does not reproduce. The paper reports history + observation compression together losing 11.4 points (interaction −9.5). On open models the interaction is +1.4 [−10.2, +12.2] (147 tasks) and 0.0 at the paper's settings.
  5. Proposed fix (state ledger): partial. A deterministic ledger of executed state and recent errors, appended to ACON's summary, fully recovered accuracy on dev (42.9% → 73.2%, p = 0.0015). On the held-out test set it helps less: 45.2% → 52.4% (p = 0.13, not significant), still far below the 4,096 setting. The dev result was optimistic because the ledger was developed on train/dev trajectories.

Status: all experiments are complete, including the held-out test set (4 arms × 168 tasks). On the test set, ACON at the paper's setting reaches 70.2% against 61.9% without compression.

* Of the compressions whose input history contains failed executions, the share whose LLM-written summary mentions a failure (keyword test). CFR = share of facts the uncompressed run later used in its code (literals and variable names) that appear verbatim in what the agent sees after compression. Per-task CFR does not predict success (r = −0.08, 390 task-runs).

  • Ruled out: loss of exact values (the naive guideline keeps fewer and still works), loss of the access token (the agent reuses the variable), loss of the API list (every arm drops it), the agent switching to prose (2–5% everywhere), and exact action loops (similar everywhere).
  • Supported: the optimized guideline drops failure information. The prompts differ exactly here: D.5 says "Include key info from errors or failed attempts to prevent repeated mistakes"; D.7 says "Delete tool/API log output".
  • Why only at 512: 510 compressions on 57 tasks (about 9 per task) erase the failure record repeatedly; at 4,096 there are 39 (under 1 per task).

At the paper's setting ACON beats no compression by 8.3 points on held-out tasks with 31% fewer agent tokens (p = 0.08). At 512 it loses 16.7 points against no compression (p = 0.001).

The collapse replicates strongly on unseen tasks. The ledger's full recovery on dev does not: it was designed and debugged while reading train and dev trajectories, so the dev number was optimistic. The test set is the number to quote.

Contributions, as they stand

  1. A reproduction of ACON on open, local models showing it works at the paper's settings.
  2. A significant, held-out failure mode: the optimized guideline is threshold-brittle (70.2% → 45.2% on test), while the unoptimized guideline is not (dev).
  3. A mechanism: optimized guidelines delete failure information, and frequent compression turns that into repeated failed actions. Value-retention metrics such as CFR do not capture it.
  4. A non-replication of ACON's combined-compression collapse.
  5. A first fix (deterministic state ledger) that helps but does not close the gap on held-out tasks.

Literature check (Sep–Oct 2026): keeping exact values outside a summary is established practice, so the ledger itself is not a novel idea. I found no work showing that ACON-style optimized guidelines are threshold-brittle or that they delete failure information. Closest related work: Toward Reliable Context Compression for Long-Horizon Agents (arXiv 2608.06503), FOCUS (2609.37590), StateComp (2609.27298) and Beyond Token Savings (2609.32961).

Limitations

  • One benchmark (AppWorld) and one agent/compressor pair (qwen2.5 14B / 7B). The paper's guidelines were optimized for gpt-4.1, so part of the failure may come from a 7B compressor following D.7 literally.
  • The mechanism is shown by correlation across arms, not yet by intervention.
  • One run per arm apart from the repeat; the repeat agreed on 55 of 56 tasks.
  • The ledger is specific to code-writing agents and adds latency (273 s vs 168 s per task on dev) because the 512 threshold compresses often.

Next steps

  1. Intervention test of the mechanism, on dev then test: an errors-only ledger vs a values-only ledger, and a minimal guideline edit that adds D.5's "include errors and failed attempts" line back into D.7.
  2. If failure preservation is confirmed, use it as the improvement: a failure-preserving variant of ACON's guideline that keeps accuracy at aggressive thresholds.
  3. A second agent model, and OfficeBench, to show the effect is not specific to qwen2.5 or AppWorld.
